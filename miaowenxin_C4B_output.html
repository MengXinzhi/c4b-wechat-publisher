公众号编辑器有多"挑剔"？

如果你直接把网页 HTML 粘贴进公众号编辑器，会遭遇一连串静默失败：

  • <h1> 被禁——标题会被降级或删除
  • <div> 被禁——布局直接散架
  • <script>、<iframe> 被禁——所有交互内容消失
  • <style> 标签被禁——所有 CSS 必须逐个写在 style="" 属性里
  • 外链图片可能丢失， SVG 保存即蒸发

📘 知识点
公众号编辑器本质上只接受一个"白名单 HTML 子集"： p、 h2、 h3、 ul、 ol、 li、 span、 img、 a、 table 等，且所有样式必须内联。

所以，从 Markdown 到一篇排版好看的公众号文章，中间隔着一整套脏活：标签过滤、样式内联、中文排版优化。这正是"技能"该干的活。

拿来主义：从 starter kit 出发

C4B 挑战附赠了一份 starter kit：一个 convert_to_wechat.py 脚本，已经能读 Markdown 和 Word、过滤违规标签、套上基础的 inline CSS。

我先跑通了它，然后对照挑战给出的"缺失能力清单"做减法：哪些能力对我的真实写作流程最有价值？

🔧 实践
不要试图一次补齐所有缺失能力。挑你最常用的两三个先做，跑通后再迭代。

我最终选了 7 项，但按"先交比不交强"的原则分了优先级：多主题和 callout 框是刚需，目录和元数据是长文刚需，中文间距是专业感的分水岭。

用 skill-creator 改造：不是写代码，是走流程

这次挑战最特别的要求：必须用 skill-creator（做技能的技能）来开发技能。

它把开发过程拆成了固定节奏：定义技能边界 → 规划可复用资源（ scripts / references / assets）→ 写 SKILL.md → 设计 eval 用例 → 打包验证。真正写代码只占其中一环。

⚠️ 注意
skill-creator 的打包验证会检查 SKILL.md 的 description 字段格式，比如不能包含尖括号——这种坑只有跑一遍才知道。

改造过程中我踩了一个典型的坑： Markdown 引擎会把连续的引用块合并成一个 <blockquote>，我最初按"每个 blockquote 一个 callout"来写逻辑，结果四个高亮框只有一个生效。修正方案是逐段落识别标记符号，再拆分成独立的框。

💡 提示
写 eval 用例时，一定要让用例覆盖"你自以为没问题"的路径。这个 bug 就是 eval 第一轮就抓出来的。

三点收获

第一， AI 时代的杠杆是"流程"，不只是"代码"。 skill-creator 教我的不是怎么写 Python，而是怎么把一次性的转换需求沉淀成可复用、可验证、别人拿到就能用的技能包。

第二， eval 不是仪式，是安全网。 如果没有第一轮 eval，那个 blockquote 合并的 bug 就会潜伏到我真正发布文章的那天。

第三，好排版是内容的一部分。 中英文之间那个小小的空格、高亮框里那个 emoji 标签，读者未必说得出哪里好，但能感觉到"这篇不像随手发的"。

你也可以试试

如果你也想把自己的写作流程变成技能：

  1. 找到你重复做的事情（比如每次发公众号前的排版）
  2. 用 skill-creator 走一遍：边界 → 资源 → SKILL.md → eval → 打包
  3. 从 starter kit 出发，别从零开始——先理解，再改造，最后署上自己的名字
